# 作者是怎么做图的：UGC 美术管线的真实形状

> 这份笔记只解决一个问题：**头部作者把一张图/一个资产做成能上架的样子，中间到底经过哪几步，每步的硬约束来自哪里。**
>
> 所有结论都指向目录里可点击的原始文档（官方规格页 / 编辑器手册 / 平台教程）。平台规格会改版，**以官方页的当期内容为准**，本页只负责告诉你"该去看哪一页、看什么字段"。

## 0. 先把"做图"拆成三种不同的活

同一个词"做图"，在不同平台上完全是三种工种，硬约束也完全不同。先认清自己落在哪一格，能省掉一半返工：

| 交付物类型 | 代表平台 | 作者实际在做什么 | 硬约束在哪 |
| --- | --- | --- | --- |
| **3D 资产（PBR 管线）** | Roblox | Blender/Maya 建模 → 冻结变换 → UV → 烘焙 PBR 贴图 → 按三角面预算导出 | [Roblox 建模通用规格](https://create.roblox.com/docs/art/modeling/specifications)：单网格 ≤ **20,000 三角面**、必须水密、禁 N-gon、禁零厚度、骨骼变换冻结到 scale(1,1,1)/rot(0,0,0)、单顶点 ≤ **4 骨骼影响**、单次导出**只允许一条动画轨** |
| **编辑器内资产（拼装+逻辑）** | 蛋仔派对、元梦之星、迷你世界 | 在编辑器里搭场景、调组件/皮肤、写规则与触发器，美术资产多用官方元件或上传资源包 | 各自编辑器手册：[蛋仔工坊手册（PC）](https://u5-creator.s3.game.163.com/manual/pc)、[迷你世界开发者学院](https://dev-wiki.mini1.cn/courses/article/955)、[元梦之星星世界编辑器](https://www.taptap.cn/moment/456219695461171265) |
| **像素贴图/低模** | 我的世界 | Blockbench 里做低元素数模型 + 像素贴图，皮肤是固定网格的两层贴图 | [Blockbench Minecraft 风格指南](https://www.blockbench.net/wiki/guides/minecraft-style-guide/)：元素数最小化、box UV、**纹理像素与模型像素 1:1**、实体贴图需"顶部/正面比底部/背面亮" |

## 1. 通用四步（无论哪种交付物都逃不掉）

**第一步：概念与三视图。** 先定"玩家在缩略图里能看到什么"。UGC 的第一评价场景是**商店/大厅列表页**，所以构图要按缩略图而非原画尺寸来推：主体居中、轮廓清晰、背景压暗、颜色控制在 3 个主色以内。这一步的产出不是"好看的画"，而是**可交付给下一步的比例与配色约束**。

**第二步：资产制作（模型/贴图/组件）。** 关键在于**先对齐规格再开始细化**。Roblox 这条线上，作者的典型返工都发生在"模型做完了才发现变换没冻结、面数超了、有 N-gon"——这类问题在 [通用规格页](https://create.roblox.com/docs/art/modeling/specifications) 上是逐条列明的硬门槛，建模阶段一次性对齐成本极低，后期补做成本极高。

**第三步：规格对齐与导出。** 按平台的规格页导出（模型设置、贴图通道、动画轨数量），再导入编辑器做视觉校验。Roblox 有专门的[导出设置说明](https://create.roblox.com/docs/art/modeling/export-requirements)；蛋仔/迷你/元梦走各自的"资源包上传/自定义模型上传"入口（见各平台笔记）。

**第四步：上架图与封面。** 迷你世界的官方流程里把封面单列成一步：普通封面直接**在场景里截图**，或**自定义上传图片**（见[地图制作流程](https://dev-wiki.mini1.cn/courses/article/955) 第六节）。这一步是转化率的大头，也是最容易被"做完就发"跳过的。

## 2. 分平台工艺要点

### Roblox / 罗布乐思

- **主线**：外部 DCC（Blender / Maya）建模 → 规格对齐 → Studio 导入 → 上架 / 自用。
- **角色与配饰是独立规格体系**：刚性配饰、分层服装、角色身体各自有专属规格与导出要求，且需要**内外 cage**（命名规则：主网格名 + `_InnerCage` / `_OuterCage`）；cage 上的顶点与 UV **不要删改**，否则导入或穿戴会报错。
- **动画**：单个导出文件只能带一条动画轨，多动作要分文件导出。
- **PBR 面**：平台支持基础色贴图与现代 PBR 贴图，贴图自身的尺寸与通道规范另有专页，别拿建模规格当贴图规格用。
- **完整入口**：[Roblox 创作者中心](https://create.roblox.com/)（文档 / 创作者商店 / 分析 / 发布后台）。

### 蛋仔派对

- **编辑器是"双端同源"**：PC 端 `Eggitor` 与移动端同步更新，手册分 [移动端](https://u5-creator.s3.game.163.com/manual/mobile) 与 [PC 端](https://u5-creator.s3.game.163.com/manual/pc) 两套。
- **美术面**：组件编辑（含**组件皮肤编辑**）、特效编辑器（有光束/粒子法阵实例教学）、生物组件（**蛋仔类骨骼说明**、行为树可自定义 AI 行为）、以及**资源包上传与自定义模型上传**。
- **逻辑面**：蛋码（积木/触发器）+ Lua（含 `EditorCli` 与调试工具、API 手册按周更新），也就是说"会写代码"这条线在这里有正收益。
- **资产面**：官方资产目录直接给出**蛋仔时装套装 / 配饰 / 外观散件**清单——先查资产目录再决定是否自制，是省时间的常规做法。
- **商业化在编辑器内部**：激励方式、商品、广告、盲盒、会员权益都在手册的"商业化"章节，做之前先读激励规则。

### 元梦之星（用户口述的"圆梦之星"）

- 基于 **UE4** 的 UGC 编辑器「星世界」，官方元件**免费且无需解锁**，并专门打包了国风素材库。
- 面向新手的功能如**路点运动单元**（选几个点即可生成复杂运动轨迹），本质是把"脚本能力"包装成可视化操作。
- 创作产出可上传到**模组社区**；「造梦计划」给现金/流量/培训类奖励（见平台官方公告与[编辑器介绍](https://www.taptap.cn/moment/456219695461171265)）。

### 迷你世界

- 官方推荐 **PC 桌面版**创作（效率更高），流程是：申请开发者（[星启计划](https://activities.mini1.cn/fe/starPlan)）→ 迷你盒子激活开发者权限 → 开发者模式建图 → 场景搭建（可用**地形编辑器**）→ 插件/道具/怪物等元素 → **微缩模型**制作 → 规则与触发器 → 转玩法地图后公开上传 → 封面。
- **微缩模型**是这条线区别于其他平台的特色：模型在游戏内制作，门槛低但风格受工具能力约束。
- 封面：普通封面直接截图，或自定义上传图片。
- 变现：迷你豆/迷你币/广告收益 + 开发者商店 + 商业化广告触发器，另有**签约工作室扶持**与开发者训练营。

### 我的世界

- **模型 + 贴图一套流水线**：Blockbench（[官网](https://www.blockbench.net)）做低元素数模型，贴图遵循"细节靠贴图、形状靠模型"的取向；UV 必须是 **box UV 且像素比例 1:1**，不得拉伸。
- **皮肤是固定网格**：按[中文 Minecraft Wiki](https://minecraft.wiki) 的说明，皮肤分区域对应实体表面，**宽型皮肤共 3264 个可自定义像素（每层 1632），纤细型 3136（每层 1568）**；外套层（第二层）像素略大，用于眼镜/帽子等配件。
- **风格化的可复用步骤**（[Blockbench 风格指南](https://www.blockbench.net/wiki/guides/minecraft-style-guide/)）：生成贴图模板 → 铺色块 → 加暗部与高光 → 扩充色阶、消掉 banding。
- **分发**：[Modrinth](https://modrinth.com) 等平台 + 官方创造者计划（[我的世界开发者官网](https://mc.163.com/dev)）；合规要读[粉丝与创作者使用准则](https://www.minecraft.net/en-us/usage-guidelines)。

### 奥拉星（用户口述的"奥拉热星"）

据实说明：这条线的公开生态**以玩家社区同人创作为主**（[4399 专区](https://www.4399.com/flash/35538.htm)、[TapTap 官方页](https://www.taptap.cn/app/84327)、[维基条目](https://zh.wikipedia.org/zh-hans/%E5%A5%A5%E6%8B%89%E6%98%9F)），**缺少面向外部创作者的官方规格页与资产上传通道**。因此"做图"在这里更多是**设定图/同人图**，而不是可上架的资产。要把它纳入流水线，第一步是先确认平台的官方创作入口是否存在、条款是否允许二次创作与商用。

### 发布渠道（B站 / 抖音 / 小红书 / TikTok）

作品做完不等于交付完成：**发布环节自身有规则成本**。四个平台的社区规则/AI 内容标识要求都已收录在目录的"政策与合规"类别里。工程化做法是：把"标题/封面/话题/合规声明"做成模板与检查清单，发布前逐项打勾，而不是每次临场想。

## 3. 常见的返工点（按出现频率）

| 返工点 | 症状 | 一次做对的姿势 |
| --- | --- | --- |
| 变换未冻结 | 导入后缩放/朝向错乱、骨骼影响异常 | 建模基准阶段就冻结 scale=1,1,1、rot=0,0,0（Roblox 明确要求） |
| 面数/元素数超预算 | 上架被拒或运行时掉帧 | 先按预算做灰模，细化前先卡住总量 |
| 非四边面 / N-gon / 零厚度 | 导入报错或阴影异常 | 导出前用建模软件的检查项过一遍：水密、四边面、非零厚度 |
| UV 拉伸或像素比错 | 贴图糊、像素风变形 | 像素风严格 1:1 对应；3D 先展开再画贴图，不反过来 |
| cage/命名不合规 | 配饰穿戴失败 | 主网格 + `_InnerCage` / `_OuterCage`，且不删改 cage 顶点与 UV |
| 封面随手做 | 曝光低、转化差 | 把封面当独立交付物：场景截图或自定义图，按列表页缩略图尺寸检查可读性 |
| 没查资产目录 | 重复造轮子 | 先检索官方资产库/元件库（蛋仔资产目录、元梦官方元件），再决定自制 |

把上面的"硬约束"做成**可执行检查表**（每个平台一页，标注来源页与核对日期）是仓库路线图里的第一项。如果你手上正走某条线，欢迎按 [CONTRIBUTING.md](../CONTRIBUTING.md) 把实测到的规格与踩坑点提上来——**带来源与日期**的经验，价值远高于"某某说可以"。
